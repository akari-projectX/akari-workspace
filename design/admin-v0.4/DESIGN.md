# 管理后台设计稿 v0.4（W33-a）

> 这是**设计稿**：所有数据都是虚构的，页面不连接任何接口。你确认后才开始 W33-b 的正式实现。
> 本地查看：`cd design/admin-v0.4 && npm install && npm run dev`，浏览器打开 http://localhost:5173 。
> 截图在 `screenshots/`：每个页面都有 桌面 1440px / 手机 390px × 浅色 / 深色 四张；弹窗、抽屉、加载 / 空 / 错误状态另有截图（桌面浅色 + 手机深色）。

## 1. 设计原则

1. **先看到状态，再做操作**。每个页面顶部先放能一眼看懂的数字和异常（离线、超额、探测失败、开通失败），操作按钮放在右上角或行内。
2. **详情一律在右侧抽屉里打开**，不跳页面；关闭后列表的筛选和滚动位置不变。手机上抽屉占满屏幕。
3. **危险操作两步确认**：确认框里写清楚"影响多少个 / 哪些地方"，批量删除、轮换后台前缀、修改订阅路径、删除域名还要再输入一段文字才能点确认。
4. **所有结果都有反馈**：成功 / 失败用右下角 toast（手机在底部），文案说明"已写入审计""哪些节点已收到更新"。
5. **只能做系统允许的事**：比如用户详情里没有"直接改流量 / 到期时间"的输入框（D12），也没有节点权限列表（D3）；做不到的操作直接不出现，而不是点了再报错。
6. **统一的颜色和间距**：一套颜色变量同时定义浅色和深色；绿色 = 正常，黄色 = 需要注意，红色 = 故障 / 危险，蓝色 = 信息。颜色旁边总有文字或图标。
7. **手机和平板可用**：侧边栏在 1024px 以下变成抽屉；表格在手机上变成卡片列表；弹窗在手机上从底部弹出。
8. **加载、空、错误三种状态都设计了**：加载用骨架屏（和真实布局一样的灰块），空状态告诉你下一步做什么，错误状态给出错误码和"重试"。
9. **中文优先，可切换英文**（顶栏的语言按钮）。
10. **符合面板的安全约束**：没有内联脚本（CSP 只允许 `'self'`），不依赖外部字体和 CDN。

## 3. 逐页说明

### 3.1 登录（`login-*`）
- 地址是后台秘密前缀 `akari.example/<前缀>/`（**D4**），页面底部提示"门户不会链接到这里"。
- 用**邮箱 + 密码**登录（**D1**），上方是"使用通行密钥登录"（**D7**）；**没有任何 TOTP / 验证码输入框**（D7 已移除 2FA）。
- 密码框下面是 Cloudflare Turnstile 的位置（**W27**，按表单在设置里开关）。蜜罐字段是隐藏的，看不到。
- `login-passkey-only`：开启"仅允许通行密钥登录"后只剩通行密钥按钮，并提示丢失设备时用服务器命令恢复。
- `login-bind-passkey`：用密码登录后引导绑定通行密钥，可以"稍后"。

### 3.2 仪表盘（`dashboard-*`）
- 四张卡片：今日营收（含 7 / 30 天和趋势线）、有效订阅、当前在线、节点在线 / 总数（含离线、超额、入口异常）。
- 近 14 天全网流量柱状图；"待处理"列表（工单、开通失败订单、提现、失败邮件、探测失败的入口），点击直接跳到对应页面。
- 最新订单；服务器列表带 CPU / 内存和**服务器流量额度进度条**（D5）。
- `dashboard-loading`：骨架屏。

### 3.3 用户（`users-*`）
- 表格：邮箱（未验证会标出）、状态（正常 / 已到期 / 流量用尽 / 已封禁 / 无套餐）、套餐、流量进度条、到期、注册时间、最后登录；"列"按钮可以加显示余额、在线设备、通行密钥数。
- 筛选：邮箱 / ID、状态、套餐，"更多筛选"里有 **从未使用 / 注册早于 / 最后登录早于**（**D10**），已选筛选以小标签显示，可单独清除（`users-never-used`）。
- 勾选后出现批量操作条：分配套餐 / 延长、发邮件、封禁、删除。
- **批量删除**（`users-bulk-delete`）：确认框写明"将永久删除 46 个账户"、筛选条件、删除方式（与自助注销相同：个人数据删除，有财务记录的匿名化保留），还要输入"删除 46 个账户"才能确认；执行变成后台批量任务，每个账户单独写审计。
- **用户抽屉**（`users-drawer`）：最上面是**当前订阅**卡片（**D12**）——套餐、周期、到期时间、已用 / 总流量、下次重置、限速、可用入口、状态；按钮：**重置流量**（确认框说明会自动恢复因超流量停用的账户、写审计）、续期 / 延长、更换套餐、取消套餐。没有改流量 / 到期的输入框，没有节点权限列表。下面是账户信息和**按入口统计**的近 30 天流量（R43：用户 + 入口计数）。
- **封禁**（`users-ban-dialog`，**W28**）：选择原因 + 补充说明（会显示给用户），说明会立即踢下线、订阅返回 404、写审计。`users-drawer-banned` 是被封禁用户的抽屉：红色提示条显示原因、时间、操作人，底部"解除封禁"。
- **新建用户**（`users-new`）：邮箱（管理员创建视为已验证）、初始密码（留空发邮件）、套餐 + 周期；只能"分配套餐 + 时长"或"延长 N 天"（D12）。
- `users-loading` / `users-empty`：骨架屏和空状态（带"清除筛选"）。

### 3.4 节点（`nodes-*`）——服务器 → 落地节点 → 入口
- 顶部四个数字：服务器在线、落地节点数、入口（中转 / 直连）、探测失败已隐藏的入口。
- 每台**服务器**一张卡片（阶段 0：一台机器一个 agent）：地区、主机名、IP、agent 版本（有新版本会提示）、证书剩余天数、CPU / 内存 / 速率、**流量额度**（**D5**：计费方式 双向 / 仅上行 / 仅下行、已用 / 额度、重置日）。
  - **超额状态**（日本服务器）：额度条变红、标"已超额"，下面红色提示"上面所有节点已下发空配置，下个周期或调高额度后自动恢复"，节点状态显示"超额停用"。
  - 离线服务器（新加坡）：提示租约剩余时间、入口已从订阅隐藏并已告警。
- 每个**落地节点**一行（**D2**：一个节点一种协议，派生入站不显示）：名称、协议、传输、端口、状态、授权用户 / 在线、**审计规则开关**（**W29**，默认关；关闭时确认会断开在线连接）。
- 展开后是**入口**表（**§5**）：直连 / 中转、连接地址和端口（中转显示出口 IP 个数）、倍率（有时段规则显示时钟图标和数量，**重叠时显示黄色警告图标**）、节点组、**TCP 探测**（延迟或"失败 · 12 分钟"）、**订阅中**（显示 / 已隐藏 / 已关闭）。
- **入口抽屉**（`nodes-entrance-rates`）：
  - 名称（显示订阅里的节点名，例如"香港 IPLC 2.0x"）、连接地址 / 端口、**中转机出口 IP / CIDR**（说明隔离主要靠独立凭据，IP 白名单是附加防护）、启用开关。
  - **倍率与时段规则**（**D9**）：基础倍率 + 多条规则（星期几按钮、起止时间、倍率），时区 Asia/Shanghai；**重叠时规则变黄，并写明"规则 1 与规则 3 在周五重叠，取最高 3.5x"**；下面是**一周 7×24 倍率热力图**，当前时刻有边框，顶部显示"当前倍率"。
  - 可使用的节点组（权限：套餐 → 节点组 → 入口）。
  - 删除中转入口：确认框写明多少用户会失去该入口，并要输入入口名。
- `nodes-entrance-down`：探测失败的入口，红色提示"已从订阅隐藏，已发 Telegram 告警，恢复后自动显示"。
- `nodes-quota`：服务器流量额度弹窗——计费方式三选一、每周期额度、每月重置日、本周期已用；新额度高于已用时提示"保存后立即恢复"。
- `nodes-error`：加载失败状态。

### 3.5 套餐（`plans-*`）
- 套餐卡片：价格、流量与重置方式、限速、节点组和入口数量（含中转会标出）、订阅人数 / 库存、在售状态。
- **节点组**标签页（`plans-groups`）：每个组按服务器列出包含的入口（直连 / 中转图标、倍率、已隐藏标记），并说明"低价套餐不能用中转"的原因（§5 落地机隔离）。
- **套餐抽屉**（`plans-drawer`）：名称、流量、限速、重置方式、选择节点组 → 实时列出"用户将获得的入口"、价格周期、在售开关、库存。

### 3.6 订单（`orders-*`）
- 顶部红色提示"1 个订单已付款但开通失败"。表格：订单号（开通失败带红色图标）、用户、套餐 / 周期、类型（新购 / 续费 / 换套餐 / 流量重置）、实付、方式、状态、时间；筛选状态、方式、日期范围。
- **订单抽屉**（`orders-drawer`）：开通失败的说明和"重试开通"；**金额拆分**（原价 → 优惠券 → 换套餐抵扣 → 余额 → 实付）；退款要求输入订单号后 6 位确认。

### 3.7 系统设置（`settings-*`）
左侧是设置分类（手机上变成横向滚动标签），每类标出对应的决定编号。
- **站点与域名**（**D8**）：主域名 / 订阅域名 / 节点通信域名三个列表，每类一个"首选"（星标），显示 Cloudflare 状态（节点域名必须是灰色云朵）和证书状态、"影响 N 处"。**删除前**（`settings-delete-domain`）列出会影响的地方（例如"3,402 个用户的订阅链接""客户端一键导入链接"），并要输入域名确认；首选域名不能直接删。订阅域名下有"每个用户随机分配订阅域名"开关；节点域名下说明证书 SAN 只增不减。站点名称和**站点时区**也在这里。
- **后台与登录安全**（`settings-security`，**D4 / D7**）：后台地址（默认打码，可显示）、**轮换**（`settings-rotate-prefix`：显示新旧地址、只显示一次、要输入"轮换"）、**IP 白名单**（保存前检查当前地址，附锁死时的服务器命令）。登录方式：密码登录后引导绑定通行密钥、绑定后关闭密码登录、**仅允许通行密钥登录**（管理员 / 用户分开；开启前提示还有几位管理员没绑定）。
- **订阅**（`settings-subscription`，**D11 / W30**）：订阅路径 + 随机生成 + "应用新路径"（`settings-sub-path`：写明 3,620 个用户的链接会立即失效，要输入"旧链接全部失效"）；**分流规则模板**（默认"国内直连 · 国外代理 · 广告拦截"，geosite / geoip 规则表，可拖动排序）；一键导入客户端开关（Clash Verge、mihomo、Shadowrocket、sing-box、Stash、Hiddify）。
- **注册**（`settings-signup`，**D1 / W27**）：开放注册、注册需要验证邮箱、注册需要邀请码（两个开关独立，默认关）、试用套餐；Turnstile 密钥和**按表单开关**（登录 / 注册 / 找回密码）；蜜罐 + 最短提交时间（默认开，显示命中次数）。
- **邮件**（**W31**）：SMTP（465 隐式 TLS / 587 STARTTLS）或 **Resend API**；**测试发信诊断**（`settings-mail-test`）逐步显示：解析域名 → 连接端口 → TLS 握手 → 认证 → 发送，失败的一步标红，并用中文写出可能原因（例如"需要授权码而不是登录密码"）。
- **审计规则**（`settings-block-rules`，**W29**）：内置规则集（BitTorrent 协议识别、BT Tracker 域名、迅雷 / PT 域名）和自定义规则集，各自开关并显示近 7 天拦截次数；说明只统计节点拦截次数、不记录用户访问明细；自定义规则编辑（域名 / IP / 协议）。
- **账号清理**（`settings-cleanup`，**D10**）：自动清理（默认关）、天数 N（默认 30）、删除前邮件提醒；显示"现在有 46 个账号符合条件"并可跳到用户列表的对应筛选。

### 3.8 系统状态（`status-*`，**W31**）
- 面板机器：CPU（含负载）、内存、磁盘的环形图，运行时间。
- 依赖服务：PostgreSQL、Valkey、Caddy 的版本和关键指标。
- 面板实例：每个实例的版本、运行时间、agent 会话数、当前负责的单实例任务（告警评估、对账等）。
- 后台任务：流量结算、明细压缩、支付对账、邮件发件箱、告警评估、入口 TCP 探测、账号清理——状态、周期、上次运行、说明。
- 底部提示邮件死信并可直接"测试发信"。

## 5. 需要你决定的问题

1. **每个用户随机分配订阅域名**：默认开还是关？（设计稿里画成开。）
2. **服务器流量额度怎么计**：按 xray 统计的用户流量（与计费一致，但不含协议开销和非代理流量），还是按网卡流量（与服务商账单一致）？
3. **封禁后能否登录门户**：设计稿是"能登录、只看封禁原因和提交工单"，订阅和节点全部停止。你希望完全不能登录吗？
4. **管理员"延长 N 天"**：不产生订单，也不收费。是否对所有套餐都允许（包括一次性流量包）？
5. **仅允许通行密钥登录（管理员）**：开启前是否要求每位管理员至少绑定 2 个通行密钥，防止丢设备被锁在外面？
6. **修改订阅路径时**：是否提供"同时给所有用户发邮件告知新链接"？
7. **按筛选批量删除**：删除"全部匹配的账号"（设计稿，46 个）还是只删除"当前页勾选的"（3 个）？
8. **手机上表格变成卡片列表**：可以接受吗？还是有些表格（例如订单）宁可横向滚动？
9. **优惠券、资金、工单、内容、告警、更新、审计、我的账户**：W33-b 直接套用新外壳和组件迁移，还是要先补设计稿？
10. **审计规则的修改会重建 xray（断开节点上的所有连接）**：可以接受，还是需要"在凌晨某个时间统一生效"的选项？
