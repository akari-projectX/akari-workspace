# Red team 2026-10, area C: nodes, enrollment, update and install supply chain

Base: akari-panel origin/main a74a41b, akari-agent origin/main 40ef891. Branches `rt-c-nodes-supply-chain` in both repos (PRs listed at the end).
Method: white-box read of enroll.rs, install.rs, grpc.rs (session, identity), traffic.rs (ingest), nodestat.rs, blockrules.rs, rollout.rs, updates.rs, updatecheck.rs, entrances.rs, nodeinstall.rs/.sh, scripts/install.sh; agent updater_linux.go, sourcefilter*.go, procnet.go, release/, systemd/ and openrc/ units. Tests ran against a local PG 18 + redis, nothing external was contacted. No systemd or docker is available in this sandbox, so the unit-level consequence in C-3 is analysed, not reproduced.

## Findings (fixed, regression test fails before the fix)

| id | sev | summary | test |
|---|---|---|---|
| C-2 | medium | The instance's download slots (`max_concurrent_downloads`, 8) are shared by every node's FetchArtifact and every install-link download. One enrolled (or compromised) node can open that many streams and stop reading; a stalled reader keeps its slot up to 60 s per 1 MiB chunk (hours for a full binary), so no other node can fetch a self-update and no new node can install. The updater is the patch path for xray vulnerabilities, so a compromised node could block fleet patching. Fix: `AppState::try_fetch_slot(server)`: shared permits plus at most one running download per server (FetchArtifact and the install binary both use it). Residual: N compromised servers still hold N slots. | `redteam_c_tests::one_node_cannot_hold_every_download_slot` |
| C-1 | low-medium | Hello text (`agent_version`, `core_version`, `os`, `arch`, `session_id`) was stored unbounded in `servers` (up to the 64 MiB gRPC message limit per Hello, repeatable) and logged unbounded. Every admin list returns these columns for every server, so one compromised node could bloat the database and every admin list response; heartbeats, latency, certificate and block status were already capped through `agent_text`. Also `Ack.error` was logged before being cut to 2000 characters and `UpdateStatus.version` was logged unbounded. Fix: `grpc::bounded_hello` (versions 64, platform 16, session id must satisfy the traffic rule, control characters dropped), log after truncation, `rollout::on_status` ignores versions longer than 128 bytes. | `redteam_c_tests::hello_text_is_bounded` |
| C-3 | low-medium (agent) | The root updater consumes `apply-request.json` / `source-filter-request.json` by unlinking them. The agent owns that directory and can plant a non-empty directory under either name; unlink fails, the trigger condition (systemd `PathExists=`, the OpenRC loop's `-e` test) stays true and the updater is started again and again. Under systemd this reaches the service's start limit (default 5 starts per 10 s), after which the service and path unit are failed and self-updates and source filters stop until someone runs `systemctl reset-failed` (this last step is analysis, not reproduced). Under OpenRC it spins once a second doing a flock and a fsync'd result write. Fix: `agentDir.consume` renames an entry it cannot unlink aside (`.rejected.<pid>.<ns>`) so the trigger clears. Residual: an agent that keeps re-planting can still drive the start limit; recommended follow-up (needs the CI systemd job and a panel PR for the byte-identical unit copy): `StartLimitIntervalSec=0` on `akari-agent-update.service`. | agent `TestUpdaterClearsRequestNamesItCannotUnlink` |

## Observations without a fix (decision or design)

- **O-1 first install trusts the panel.** The install script (served by the panel, run as root) verifies the agent binary only against the SHA-256 the same panel wrote into the script. Self-updates are signed (keys compiled into the agent); the first install is not. A compromised panel can therefore run code as root on every node installed or re-installed afterwards. Option: print the release's signed manifest digest on the node page and have the script check the manifest signature with keys the operator supplies (`--release-key`), or document it in DEPLOY as the trust root of one-click install.
- **O-2 unbound-port window of source filters.** The root updater skips ports bound by another uid, but a port nobody holds at that instant is accepted; a compromised agent could ask for `ct state new drop` filters on ports whose service is briefly down (a restarting daemon) and keep re-asking. Needs a compromised agent plus a timing window; bounded by 1024 ports and by the input hook only (forwarded/DNAT traffic is unaffected). Option: only filter ports the agent itself holds at apply time (the agent binds first, then asks).
- **O-3 compromised agents can influence their own rollout row** (claim healthy, or report FAILED/ROLLED_BACK so the failure ratio halts a rollout in a small fleet). Per-server only; by design of the health gate.
- **O-4 pre-auth unary decode size.** `Renew` and `FetchArtifact` bodies are decoded (up to the 64 MiB limit of the service) before `peer_cert` runs; the enrollment service uses 64 KiB for this reason. Cost is paid in attacker bandwidth 1:1 (buffering grows with bytes sent), so left alone; a per-method body limit layer would close it.
- **O-5 blind SSRF from nodes via panel-supplied probe URLs / inbound JSON** is inherent to a trusted panel (documented: inbounds without users are open proxies, `LatencyProbeConfig.urls` are fetched by the node).
- **O-6 `latest` pointer of the installer** (`akari-panel-image.txt`) is unsigned and only picks a tag; the tag is then verified by cosign identity, so the worst case is a downgrade to an older signed release by whoever controls the release assets.

## Coverage: checked, holds

1. **Enrollment and identity.** Token 256-bit, only SHA-256 stored, single use by conditional UPDATE under the server row lock, one uniform PERMISSION_DENIED for unknown/used/expired/deleting (`token_errors_are_uniform_and_csr_checked_first`, `enroll_then_serve_and_token_is_single_use`); CSR policy strict (P-256, ecdsa-with-SHA256, no attributes, self-signature, 4 KiB) with the subject ignored and CN/EKU/validity/serial chosen by the panel (`install::tests`, fuzz `csr`); rotation/promotion/tombstones `rotated` vs `deleted`, renew from prev, rate limit 20/h (`enroll::tests`); deleted servers are served empty state then closed and never billed (`delete_while_connected_then_revoked_reconnect`); OpenChannel, Renew and FetchArtifact all call `peer_cert` and refuse revoked certificates; client certificates are verified by rustls against the CA (expiry, ClientAuth) and the server certificate carries ServerAuth only. Handshake concurrency is bounded (`handshakes_in_progress_are_bounded`). Minor: the renewal and install rate limits fail open when Valkey is down (documented).
2. **Agent session trust.** Server id comes only from the certificate; traffic is accepted only for (entrance, user) members of that server, per-session dirty cap, entry cap, row cap, rate plausibility and node GCRA, so one server cannot touch another server's counters or billing (`traffic::tests`, `db_tests`). Latency (4 results, 512-byte URLs, clamped time), heartbeat (all numbers clamped/optional, text through `agent_text`), cert status, block stats (rule ids joined to `block_rules`, 8 epochs per server), update status (scoped to its own `rollout_servers` row, version must equal the rollout's) are bounded. Gaps found: C-1.
3. **Relay entrances.** Per-entrance credentials (`entrance_users`, `stat_key`), source CIDRs re-normalised by netip in the agent and again by the root updater, nft script rendered from parsed values, fuzz `FuzzNftScript`/`FuzzFilterRequest`/`FuzzParseNetSockets`, other-uid ports skipped (`TestUpdaterSkipsPortsOtherUsersHold`), port clash covers node inbound and all derived inbounds (`entrances::tests`). Residual: O-2. Updater treats the agent directory as untrusted: O_NOFOLLOW per component, regular single-link files owned by the agent, bounded reads, request consumed first, TOCTOU-safe copy then verify, results created O_EXCL and chowned; gap found: C-3.
4. **One-click install.** Link = enrollment token, live only while unused/unexpired/server not deleting, per-address rate limit, uniform 404 (`only_live_install_links_are_served`, `install_link_lifecycle`); script values pass `sq` and the node name `tame`, heredoc delimiter checked, the token goes to curl on stdin, the pin is checked by curl before any request (`-k` only with a pin), binary verified against the digest in the script, units taken from the verified binary; uninstall script only touches its own paths (`bbr_remove` restores only values still ours). A non-owner admin choosing the origin (only when no main domain is set) cannot change the binary digest. See O-1.
5. **Self-update chain.** Manifest parsing identical rules on both sides (strict JSON, schema 1/2, rollback binding, 30-day cap), Ed25519 over a domain-separated message, no downgrade, rollback only from the exact running version, unexpired, to a version this node ran (root-only `ran` record), `rolled_back` versions never accepted again, copy-then-verify, units from `-print-units` of the verified copy, `.prev` and units restored on failure, shared vectors (`cross_language_vector`, `TestSharedVectorRollbackCases`). A compromised panel can delay or withhold updates and make nodes run any xray inbound it likes, but cannot make an agent run an unsigned, cross-platform or older binary. `updatecheck` only talks to the source host (plus GitHub download hosts), re-checks every redirect, caps sizes and stores nothing unless signature, SHA256SUMS and platform match.
6. **Panel installer.** Every download is verified: cosign (pinned by SHA-256, exact certificate identity `release.yml@refs/tags/<tag>`) over SHA256SUMS then per-file SHA-256; Valkey and Caddy by pinned SHA-256; apt keys by fingerprint; a piped installer refuses to re-download itself; admin password via environment/file only, generated passwords on stdin/heredoc, log 0600; join bundle is age-encrypted to a key shown once, 24 h expiry, member names whitelisted before extraction, links/devices rejected, deleted after use. No defect found; minor: extraction happens before the post-extraction link check (the bundle is only openable by the key holder).
