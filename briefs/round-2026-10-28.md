## Lead rulings (2026-10-28)

### Money (audit panel-billing P3-1/5/9, ops-logic-review 低-3…低-9)
- **P3-1 renewal refund and the fresh quota**: a renewal that reset used traffic (`fresh_quota`) records the used bytes it cleared in `fulfil_result`; refunding that renewal (`Effect::Rollback`) adds them back (capped at the plan quota), in the same transaction, audited. No refusal path.
- **P3-5 month-end anchor**: calendar-month periods keep the anchor day of the subscription's first purchase: a plan bought on the 31st renews to the 31st when the month has one, otherwise the month's last day (Jan 31 → Feb 28 → Mar 31). Store the anchor (`user_plans.anchor_day` or derive from the first period start) and use it in `akari_period_end`; site time zone rules unchanged.
- **P3-9 partial original-route refund**: plan effect is explicit, not implied by the amount. A refund of the full paid amount keeps today's behaviour (revoke unless `keep_plan`). A partial refund (amount < paid) defaults to `keep_plan = true` (money only); the admin may still choose to revoke. Commission: claw back proportionally (`floor(commission × refunded / paid)`); coupon redemption released only on a full refund. Preview (`refund-preview`) shows all of it.
- **低-3**: when switching out of a permanent plan (no expiry) the shop and order confirm show an explicit warning that the remaining permanent entitlement is forfeited; forfeited credit stays forfeited (no balance conversion).
- **低-4, 低-5**: verify against current code (low-4 is covered by `orders.prior_user_plan_id`/`order_admin.superseded`; low-5 by `external_cents` partial amounts + P3-9 above). Only fix what is still open.
- **低-6**: commission for an inviter who is banned stays pending (not credited) until unbanned; no "pause expiry while banned" switch (do not add).
- **低-7**: no change (commission off by default, first order only); note it in docs/PAYMENTS.md as a known limitation.
- **低-8**: orders whose payable amount is 0 (balance / credit / coupon cover it) do not require a usable payment method; the shop is not empty when no method is enabled (plans payable only with balance show a hint).
- **低-9**: hide `device_seats` in the portal until seats exist (keep the field in the API only if something uses it; otherwise drop it).

### Auth / core (audit panel-auth-access, panel-core)
- **Admin password reset by e-mail**: not added. Admin accounts recover only via the owner or `akari admin reset-login` (documented). Admin-facing e-mails never contain the admin prefix or a console link (verify; fix any that do).
- **HSTS**: send `Strict-Transport-Security: max-age=31536000` (no `includeSubDomains`, no `preload`) on responses served over https for main/sub domains when `web.cookie_secure` is true; never on the canonical rejection (byte-identical rule) — rejections stay exactly as they are.
- **`Sec-Fetch-Site`**: state-changing requests (non-GET/HEAD/OPTIONS) to `/api` and the admin API with a cookie session are refused when `Sec-Fetch-Site` is present and is `cross-site` (403 `request.cross_site`, portal/admin copy). Absent header = allowed (old clients, CLI). Payment notify, install and subscription routes are exempt.
- **E-mail verification default**: stays off (it needs mail delivery); the admin signup page shows a prominent recommendation to turn it on once mail works.
- **Installer unsigned fallback download**: remove any download path whose bytes are not checked against the cosign-verified `SHA256SUMS` (or a pinned SHA-256 in the script). No exceptions.
- **Docker base images**: pin every `FROM` (Dockerfile, compose files, CI service images where practical) by digest with the tag as a comment; Dependabot docker ecosystem keeps them current.
